# Writing a Ketcher E2E spec

Target: **$ARGUMENTS**. The suite's architecture — fixtures, page-object style, the utility catalogue
and the anti-pattern list — is [.memory-bank/testing-e2e.md](../../../.memory-bank/testing-e2e.md);
read it once per task. This skill is the authoring procedure and the conventions the existing 302
specs actually follow. Running and triaging: `ketcher-e2e-run`. Baselines: `ketcher-e2e-baselines`.

**Agree the scope first.** E2E specs are long and expensive to review; confirm which cases are wanted
before writing a suite.

## 1. Where the file goes

New specs live under `tests/specs/Chromium-popup/<Area>/` (project `chromium-popup`); the `chromium`
project holds existing tests. The folder decides the project, the base URL and the baseline suffix —
moving a file later means regenerating every baseline.

Extend an existing spec when the area already has one and it is under ~500 lines; 15 files are over
2 000 lines today and are the hardest to review — do not add to them.

## 2. Skeleton — one shared page per suite

```ts
import { Page, test, expect } from '@fixtures';

let page: Page;

test.describe('<Area>: <what is covered>', () => {
  test.beforeAll(async ({ initSequenceCanvas }) => {
    page = await initSequenceCanvas();
  });

  test.beforeEach(async ({ SequenceCanvas: _ }) => {});

  test.afterAll(async ({ closePage }) => {
    await closePage();
  });
});
```

- Pick the init fixture for the mode: `initMoleculesCanvas`, `initFlexCanvas`, `initSnakeCanvas`,
  `initSequenceCanvas`. The empty `beforeEach` exists to trigger the canvas fixture's cleanup —
  keep it.
- One test needing another mode takes the non-init fixture as a parameter:
  `async ({ FlexCanvas: _ }) => {}`.
- A test that leaves a dialog open closes it in `afterEach` behind an `isVisible()` guard. Never
  `page.reload()` in a shared-page suite.
- Imports come from `@fixtures` (`test`, `expect`, `Page`, `Locator`), `@utils…` and `@tests/pages…`.
  Only page-object files import from `@playwright/test`.

## 3. The comment block

Directly inside the test body, before the first action, in the style the suite already uses:

```ts
test('Case 1: <plain English sentence>', async () => {
  /*
   * Test case: https://github.com/epam/ketcher/issues/<N>
   * Description: <what must hold>
   * Scenario:
   * 1. <step>
   * 2. <step>
   * Version 3.20.0
   */
```

`Bug:` is added on bug-regression specs. The title carries the case number and becomes the baseline
filename — keep it stable, because renaming it orphans the PNG.

## 4. Acting on the canvas

- **Page objects first.** Interact through `tests/pages/...`; a spec should not build locators. If a
  control has no page object, add one (§6). There are 118 raw `getByTestId` calls in specs today —
  that is the habit to avoid, not an example to copy.
- **Enums, not strings.** Monomers come from `@tests/pages/constants/monomers/*` (`Peptide.A`,
  `Sugar.R`), UI values from the constants files (`LayoutMode.Snake`, `MonomerOption.Copy`). Never
  write `'A___Alanine'`.
- **Load structures with the helpers**: `openFileAndAddToCanvasAsNewProject(Macro)`,
  `pasteFromClipboardAndAddToMacromoleculesCanvas(page, MacroFileType.HELM, '…')`. Data files live
  under `tests/test-data/<FORMAT>/<feature>/`, referenced relative to `tests/test-data`.
- **Waits belong to helpers**: `waitForRender`, `waitForSpinnerFinishedWork`, `waitFor({ state })`.
  A raw `page.waitForTimeout` needs a comment saying why nothing else works (43 remain in the suite).
- Ketcher API calls go through `@utils/formats` (`getKet`, `getMolfile`, `setMolecule`), not raw
  `page.evaluate`.

## 5. Verifying

Prefer the cheapest check that can fail for the right reason:

1. **State** — `await expect(SomeDialog(page).input).toHaveValue('100.205')`, locator counts,
   attributes. Fast, stable, readable in a diff.
2. **File round trip** — `verifyFileExport(page, 'KET/<name>-expected.ket', FileType.KET)`. The
   expected file is generated by a `GENERATE_DATA=true` or `--update-snapshots` run; review it before
   committing. Passing `metaDataIndexes` replaces the default keyword filter (`-INDIGO-`, `$DATM`,
   `$MDL`, `Ketcher`) with line numbers — do not pass it unless you mean exactly that.
3. **Screenshot** — `takeEditorScreenshot(page, { hideMonomerPreview: true, hideMacromoleculeEditorScrollBars: true })`
   for canvas output, `takeElementScreenshot` for one element. `takePageScreenshot` ignores those two
   options, so it captures previews and scrollbars. Use a tolerance (`maxDiffPixels`,
   `maxDiffPixelRatio`) only for genuinely noisy areas, and say why in a comment.

A new baseline is created by running the spec in Docker — see `ketcher-e2e-baselines`.

## 6. New page object or enum

A page object is a factory function, never a class, in `tests/pages/{common,molecules,macromolecules}/`
(dialogs under `canvas/`). There is no barrel to update — the file is imported by its full path:

```ts
import { Page, Locator } from '@playwright/test';

type ExampleDialogLocators = { window: Locator; okButton: Locator };

export const ExampleDialog = (page: Page) => {
  const locators: ExampleDialogLocators = {
    window: page.getByTestId('example-window'),
    okButton: page.getByTestId('example-ok'),
  };
  return {
    ...locators,
    async ok() {
      await locators.okButton.click();
      await locators.window.waitFor({ state: 'detached' });
    },
  };
};
export type ExampleDialogType = ReturnType<typeof ExampleDialog>;
```

Methods wrap their own waits. Enum values in `tests/pages/constants/**` are the raw `data-testid`s —
check the id against the product source (a toolbar button's id is its action key) before adding it.

## 7. Known-broken tests

- Tag the test and say why: `test('…', { tag: ['@IncorrectResultBecauseOfBug'] }, async () => {` with
  an `IMPORTANT:` line naming the issue. The baseline then records the buggy output until the fix.
- For data-driven rows use `test.fixme(row.shouldFail, \`…${row.issueNumber}\`)` — and place it
  **before** the assertion it is meant to skip; after a failing `toHaveScreenshot` it never runs.
- Tags are documentation: no config, script or CI job filters on them, so a tagged test still runs
  and still gates the merge.

## 8. Before handing over

- `npm run check:autotests` from the repository root (tsc + ESLint for the suite; CI does not run it).
- The spec passes alone: `ketcher-e2e-run` with its path, and once more to expose flakiness.
- Baselines regenerated in Docker and reviewed; orphans checked (`ketcher-e2e-baselines`).
- No `@playwright/test` import in the spec, no hardcoded monomer id, no unexplained
  `waitForTimeout`, file under ~500 lines, every test has its comment block with the issue link.
