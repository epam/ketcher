# Tracker

Ketcher tracks work in GitHub issues on `epam/ketcher`, through the `gh` CLI.

## Issues

- **Kind.** A bug is an issue of type `Bug` (not a label). Features are type `Feature`, other work type `Task`. List open bugs: `gh issue list --state open --search "type:Bug" --limit 500`. File one: `gh issue create --type Bug --title <title> --label <area label> --body-file <file>` (one `--label` per label).
- **Area labels.** Pick from `gh label list` the labels for the area the fix lands in (`Macromolecules`, `Sequence mode`, `Monomer Library`, `Export to KET`, and so on). Leave `Priority:` and `Severity:` labels to the maintainers.
- **Titles.** A bug title states the wrong behavior as a plain sentence, in the terms of [glossary.md](../../../.memory-bank/glossary.md). Read the titles of recent bugs first and match them.
- **Read** an issue with its comments: `gh issue view <N> --comments`.

The repo has no triage labels for agents. A run records each issue's triage outcome in its run directory.

## Writes on the tracker

Filing an issue, commenting, and closing are visible to every Ketcher contributor. A flow does them only at the step that names them. Every comment starts with the line `> *Generated by AI during a ketcher-flow run.*`

## Pull requests

- **Title:** `#<issue> - <issue title>` (the PR template's pattern). With no issue, a short plain title.
- **Body:** written with the `ketcher-pr` skill ([its SKILL.md](../ketcher-pr/SKILL.md)), which fills `.github/pull_request_template.md`. Under its Evidence, "Verified in the app" carries the verdict and evidence from [VERIFY.md](VERIFY.md), or `n/a` and the reason.
- **Open**: `git push -u origin <branch>`, then `gh pr create --base <base branch> --title <title> --body-file <file>`. Add `--draft` when review is still to come, and mark it ready (`gh pr ready <N>`) when review has stopped.
